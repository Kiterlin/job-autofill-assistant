## 方案对比

### 方案1: chrome.storage.local ⭐⭐⭐⭐⭐（当前使用）

**优点：**
- ✅ Chrome 官方 API，稳定可靠
- ✅ 异步操作，不阻塞 UI
- ✅ 容量：5-10MB（足够存储简历资料）
- ✅ 无需额外依赖
- ✅ 所有参考项目都用这个
- ✅ 代码简单，易维护
- ✅ 支持 Service Worker

**缺点：**
- ❌ JSON 序列化，不支持复杂查询
- ❌ 无索引，大数据量时性能下降

**适用场景：**
- ✅ 配置数据
- ✅ 用户资料
- ✅ 简历信息
- ✅ 设置选项

**数据量估算：**
```
单套简历资料：~5-10 KB
10套资料：~50-100 KB
简历文件（Base64）：~200-500 KB/个
总计：< 1 MB（远低于5MB限制）
```

---

### 方案2: IndexedDB ⭐⭐⭐

**优点：**
- ✅ 浏览器原生 API
- ✅ 支持索引和复杂查询
- ✅ 容量大（50MB+）
- ✅ 支持事务

**缺点：**
- ❌ API 复杂（回调嵌套深）
- ❌ 代码量增加 50%+
- ❌ 需要额外封装

**适用场景：**
- 填充历史记录（数千条）
- 职位收藏管理
- 网申进度追踪

**结论：**
当前**不需要**！未来功能可考虑。

---

### 方案3: SQLite（sql.js）⭐

**优点：**
- ✅ SQL 查询强大
- ✅ 关系型数据库
- ✅ 熟悉的语法

**缺点：**
- ❌ Chrome 扩展**不原生支持**
- ❌ 需要 WebAssembly 封装（sql.js）
- ❌ 增加 **500KB+** 体积
- ❌ 性能不如 IndexedDB
- ❌ **所有参考项目都没用**
- ❌ Service Worker 兼容性问题

**结论：**
**不推荐**用于 Chrome 扩展！

if (chrome.runtime.lastError) {
  console.error('保存失败:', chrome.runtime.lastError);
  reject(chrome.runtime.lastError);

### 2. 数据大小检测

```javascript
// 保存前检查大小（5MB限制）
const sizeInBytes = new Blob([dataStr]).size;
if (sizeInBytes > 5 * 1024 * 1024) {
  throw new Error('数据过大，超过5MB限制');
}
```

### 3. 数据验证

```javascript
validateData(data) {
  if (!data || typeof data !== 'object') return false;
  if (!Array.isArray(data.profiles)) return false;
  if (!data.settings) return false;
  return true;
}
```

### 4. 数据修复

```javascript
// 自动修复损坏的数据
fixData(data) {
  if (!data.profiles) data.profiles = [];
  if (!data.settings) data.settings = {};
  return data;
}
```

### 5. 防抖保存

```javascript
// 避免频繁写入
async saveAllDebounced(data) {
  clearTimeout(this.saveDebounceTimer);
  this.saveDebounceTimer = setTimeout(() => {
    this.saveAll(data);
  }, 500);
}
```

  } else {

## 容量管理

### 当前限制

- **Chrome Storage API 限制：** 5-10 MB
- **推荐保持在：** < 4 MB
- **警告阈值：** 4 MB
- **禁止保存：** > 5 MB

### 数据大小估算

| 数据类型 | 单个大小 | 10个大小 |
|---------|---------|----------|
| 基础信息 | ~500 B | ~5 KB |
| 教育经历 | ~1 KB | ~10 KB |
| 工作经历 | ~2 KB | ~20 KB |
| 项目经历 | ~3 KB | ~30 KB |
| 完整资料 | ~8 KB | ~80 KB |
| 简历文件(Base64) | ~300 KB | ~3 MB |

**建议：**
- 最多保存 **5套完整资料**
- 简历文件控制在 **1MB以内**
- 定期清理不用的资料

## 常见问题

### Q: 保存失败怎么办？

**可能原因：**
1. 数据超过 5MB 限制
2. 浏览器权限被禁用
3. 磁盘空间不足

**解决方案：**
1. 删除部分简历文件
2. 检查浏览器设置
3. 清理磁盘空间

---

### Q: 数据会丢失吗？

**Chrome Storage 特点：**
- ✅ 持久化存储（除非手动清除）
- ✅ 扩展卸载后数据保留
- ✅ 浏览器更新后数据保留

**建议：**
- 定期导出备份（每周一次）
- 重要操作前先备份

---

### Q: 为什么不用 localStorage？

**localStorage 缺点：**
- ❌ 只能在 Content Script 中访问
- ❌ 容量小（5-10 MB）
- ❌ 同步操作，阻塞 UI
- ❌ Service Worker 不支持

**chrome.storage 优点：**
- ✅ 所有脚本都可访问
- ✅ 异步操作
- ✅ Service Worker 支持

---

### Q: 能否升级到 IndexedDB？

**可以，但不建议现在升级：**

**当前数据量：** < 1 MB  
**IndexedDB 收益：** 不大  
**代码复杂度：** +50%

**建议：**
等到有以下需求时再升级：
- 填充历史记录（数千条）
- 职位管理系统
- 复杂查询需求
